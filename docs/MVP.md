# MVP 范围说明

这份文档记录第一版**为什么这么做**，以及**刻意不做什么**。范围决策比功能列表更容易被遗忘，也更容易在后续迭代里被无意识推翻。

## 要解决的核心问题

做 AI 全栈工程师，卡点从来不是「找不到资料」——免费优质资料多到看不完。真正的卡点是：

1. **不知道学什么、按什么顺序学** —— 资料是碎片化的，没人告诉你 TypeScript 和 RAG 之间还差什么
2. **学完不知道会不会** —— 看完视频感觉懂了，一动手就废
3. **学着学着就断了** —— 没有进度感，三天热度

所以 MVP 只做一件事：**把这三个问题闭环起来**。

```
今天该学什么 → 打开课程 → 被检验 → 知道自己学会了没 → 知道下一步
```

只要这个闭环成立，内容可以后补；闭环不成立，功能做再多也留不住人。

## 五个 P0 模块

### 1. 学习路径（6 个阶段）

`foundation → llm-core → rag → agent → engineering → capstone`

阶段划分的依据不是「知识点分类」，而是**能力依赖关系**：
不会写 HTTP 服务就调不通 LLM API；检索质量不可靠，Agent 只会在错误基础上反复试错。
所以顺序是刚性的，前一阶段完成度达 80% 才解锁下一阶段（留一个提前窥探的口子，避免卡死）。

### 2. 资源库（外部免费课程 + 筛选）

**平台不生产课程正文**，只做策展。每条资源记录：标题、链接、提供方、语言、难度、形式、时长、主题、一句话中文说明、免费范围说明。

筛选维度刻意对齐真实的决策场景：

- 语言 —— 中文资源的质量已经够用，不该默认逼人看英文
- 时长 —— 「我有 3 小时」和「我有 3 周」该拿到不同的推荐
- 形式 —— 有人只能看视频，有人只看文档

### 3. 阶段自测（唯一的自产内容）

每个阶段 6 道选择题，正确率 80% 通过，答错给解析。

出题原则：**考理解与判断，不考 API 记忆**。
错误选项是「看起来合理的常见误解」，比如「temperature=0 输出就确定了」「把上下文里的旧消息静默截断」——这些是真实会踩的坑，而不是凑数的干扰项。

这是整个平台唯一需要自己做内容的地方，也是它区别于普通导航站的地方。所以有 `seed/validate.ts` 做机器校验：选项数、答案下标越界、每阶段最少题数、id 唯一。

### 4. 进度追踪

三种状态：`想学 / 在学 / 已完成`。

**完成规则**（刻意做成可解释的）：

- 阶段完成 = 该阶段资源全部标记已完成 **且** 自测通过
- 完成度 = 资源占比 75% + 自测得分率 25%；**未完成时封顶 99%**，避免进度条显示 100% 却没完成
- 没有自测题的阶段完全按资源算 —— 否则会出现「一个资源都没开始却显示 25%」的怪现象

### 5. 账号与云端同步

邮箱注册登录，进度存服务端。注册只需邮箱和密码，没有任何多余步骤——学习类产品最大的流失点就是第一次打开时的注册墙。

## 明确不做（以及为什么）

| 不做 | 原因 |
| --- | --- |
| **AI 陪练对话** | 价值高但成本也高：需要 API Key、有调用费用、要处理限流与失败。放在 V2，先把闭环跑通 |
| **自建课程正文** | 版权风险 + 内容维护成本极高，且已成规模的免费课程已经做得更好 |
| **代码沙箱** | 工程量最大（Monaco + 隔离执行 + 依赖管理），MVP 阶段用「自测题 + 外链课程里的练习」替代 |
| **支付 / 会员** | 不解决核心问题 |
| **社区 / 排行榜 / 打卡分享** | 社交激励是留存手段，不是学习手段。在闭环成立之前引入，只会稀释焦点 |
| **移动端原生 App** | 响应式布局已经够用 |
| **微服务 / 消息队列 / 缓存层** | 单机 SQLite 完全撑得住；过早优化会让代码难以理解和修改 |

## 验收标准

不是「功能列表都打勾了」，而是：

> **你自己能连续用它学满 7 天，并且每个阶段结束时真的做完了自测。**

功能齐全但自己不用，就是失败。

## 已知的取舍与遗留问题

这些是有意接受的债务，不是遗漏：

1. **没有邮箱验证与找回密码** —— MVP 自用足够；开放注册前必须补上
2. **没有速率限制** —— 注册和登录接口可被暴力尝试；生产部署前需要加
3. **CSRF 依赖 SameSite=Lax** —— 同源部署下够用；如果前后端分离到不同域，需要补 token 方案
4. **资源链接会失效** —— 有 `verified` 字段和人工核实流程，但还没有自动检测死链的机制
5. **题目是固定的 6 道** —— 重复作答会记住答案；后续可以扩题库并随机抽题

## 下一步的优先级

按「对闭环的增益 / 实现成本」排序：

1. **AI 陪练**（阶段页内嵌，带当前阶段上下文）—— 收益最大，直接解决「卡住没人问」
2. **死链检测**（定时任务 + 告警）—— 成本极低，直接影响资源库可信度
3. **题库扩充 + 随机抽题** —— 让自测可以反复做而不失效
4. **学习笔记** —— 把「学过的」变成「能讲出来的」
5. **评测驱动的内容迭代** —— 用答题数据定位「大家都答错的题」，反推是题目有问题还是资源没讲清楚
